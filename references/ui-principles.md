# 页面与界面原则

用于代码动效、录屏最终排版、示意界面与素材展示。依据用户对样片的反馈补充；与旧示例冲突时，以本页的清晰度和简洁要求为准。深色点阵是背景风格，不要求主体、图片和界面也全部变暗。真实录屏保留原站外观、桌面布局和比例，通过取景、推拉与平移改善观看，不把网站改成竖屏来迎合交付画幅。

## 1. 主题清晰，元素少

每个镜头只突出一个主体、一个关键动作或一组明确对比。先确定观众第一眼该看哪里，再安排其余内容。不能帮助理解当前动作的图标、角标、按钮、装饰线和背景元素就删掉；不为了填满画面添加内容。留白用来突出主体，主体本身仍要足够大、看得清。

桌面录屏的视觉重点也要重新构图：例如搜索框和查询内容应在中央且足够大，而不是原网页框在顶部就照样贴顶交付。按[构图与口播组合](framing-and-layout.md)给四周留安全余量，在手机尺寸下确认可读；边缘可以保留正常内容，但不能承载当前重点。人的反应、画面结果、两者同等重要分别选择纯口播、纯画面／小圆头像、上下各半，不拿多个UI窗口填满所有空间。

## 2. 颜色与对比清楚，界面有质感

背景、主体、关键状态之间要有清楚的明暗或颜色差异。深色背景可以搭配明亮图片、浅色内容区或更亮的主体表面；不要把深色背景、深色卡片、深色图片叠在一起，只靠几乎看不见的细边线区分。荧光黄绿用于必要强调，不把整页文字都染成强调色。

先用主体面积、明暗和留白解决辨识，再考虑轻微边线或阴影。不要依靠厚阴影、强发光、玻璃模糊与更多卡片制造所谓质感。质感来自清晰素材、整齐对齐、适当间距、克制圆角以及一致的细节处理。

在实际交付的预览尺寸检查：第一眼能否找到主体，按钮和状态是否可辨，次要内容是否仍可读。必要内容不使用接近背景的灰色；可用文字与其实际底色的对比度作为辅助检查，普通文字参考至少 4.5:1。截图和照片还需亲看主体细节，不能只凭色值判定清晰。截图蒙版只压暗周围环境，不能连要看的素材也一起压暗。

## 3. 让图片和动作说明，少写解释

能用图片、实际操作、前后对比或一个明确动作讲清楚，就不再加一段解释相同意思的文字。不要出现“画面展示一次、标题说一次、卡片正文再说一次”。不为每张图加标题与说明，不把口播逐句复制进界面。

保留真实界面的必要文字、输入内容，以及辨认操作对象或比较双方确实需要的短标签；用户明确要求的文字照常保留。删掉冗余解释后，仍应能看懂主角、动作与结果；看不懂时先改图片选择和动作设计，不先堆字。

## 4. 结构扁平，避免层层套卡片

主体能直接放在背景上，就不额外包卡片。需要容器时，只保留表达真实边界或操作区域所必需的那一层，优先用位置、间距和对齐区分内容。避免“外框包面板、面板包卡片、卡片再包图片框和说明框”。动效实现所需的包装层不应自动画成可见的边框和背景。

前后对比尽量在同一位置切换或扫描揭示，不额外制造多层展示框；上传动作只保留素材与必要落点。真实网站原有的结构如实录制，不为了简化而删除真实功能或伪造界面。

## 观看检查

在开场、动作中段和结果停留时检查：主体是否一眼可见，暗部是否糊成一片，文字是否重复画面，是否存在可删掉的装饰或嵌套容器。以实际预览尺寸观看连续画面；不能只看放大的终态截图。四项不过关时，先删减、拉开对比、放大主体，再调整细节。

## 本次明确的排版要求

六网站名称使用风格一致的粗体、统一字号与网格对齐，检查实际文字宽度和间距。用户要求的提示词卡片保留一层白色外框，展示当前案例填好的正文；不以“少卡片”为由删除明确要求。高亮在真实控件原位，用圆角矩形，具体见[连续录屏与提示词展示](continuous-screen-direction.md)。
