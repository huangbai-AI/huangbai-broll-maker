# 执行、合成与验收

## 镜头表

用最少字段把“这句台词为什么配这个画面”写清楚，脚本已经明确的参数不再逐项询问。先按[表格规范](storyboard-table.md)形成“阶段｜内容｜画面说明参考”，用户已有表格则沿用。下列执行记录按连续画面组建立；每组可以包含多组半句与对应动作，表格内默认按半句对应，画面完全一致且连续的相邻半句可合行，必要时用空白行补齐左右高度，不为每个动作另建一镜。

```json
{
  "format": {"width": 2160, "height": 3840, "fps": 30},
  "shots": [
    {
      "id": "shot-01",
      "cue": "点击预览，就能看见结果",
      "sourceTime": null,
      "relativeStart": 0,
      "duration": 6,
      "mode": "recording",
      "purpose": "证明预览入口与真实结果",
      "presentation": "screen",
      "presentationReason": "这一句强调界面结果本身",
      "portraitOverlay": "none",
      "capture": {"layout": "真实横屏桌面", "backend": "screenstudio"},
      "focus": {"target": "预览入口与对应结果", "outputAnchor": [0.5, 0.47]},
      "camera": {"plan": "先定位入口并推近，点击后移动到结果，停留阅读", "uniformScale": true},
      "safeArea": "按framing.json起点结合实际平台遮挡调整",
      "source": "用户提供的网页或素材",
      "beats": ["定位目标", "点击", "结果出现", "停留阅读"],
      "success": "实际预览区域出现，内容与预期一致",
      "output": "shot-01.mp4"
    }
  ]
}
```

`sourceTime:null` 表示时间尚未从原视频／转写中确认，不能把 `relativeStart` 当作原视频的绝对时间。`source` 使用真实已授权来源，不把示意值拿去访问。

三类补画面分别使用 `mode: "recording"`、`"explanatory-animation"` 或 `"ai-video"`；画面组合另记 `presentation: "talking-head"`、`"screen"` 或 `"split"`，纯画面中的圆头像再记 `portraitOverlay`。纯口播段可以没有B-roll类型，不为凑三类素材改成辅助画面。同一段台词实际切到不同画面时拆成对应镜头；多种素材在同一连续画面里叠加则保留一镜，在层级记录中分别注明来源、真实／示意属性与动作。AI镜头另记生成参数与确认记录。沿用已有工程字段即可，关键是把这些决定写清楚。

录制尺寸、源内容比例和最终竖屏尺寸分别记录；取景与平移的源坐标来自当次真实画面，不能拿示例值直接操作。关注对象的可读范围、安全区和人物遮挡在动作中间也要核对，不能只检查最终中心点。

## 动效落地

- 默认先读取[黄白口播辅助动画标准](huangbai-broll-standard.md)，用实际获准素材设计本镜构图。`assets/motion-starter.html` 只用于理解扫描／连续拖入机制，`style.css` 提供色板；示意UI和素材不能原样当成正式美术。模板 `renderAt(t)` 可任意定位，`previewPlaying=false` 后可按秒截图，不代表真实软件操作。
- 制作独立配画时，确需批量导出、多素材合成或可编辑动效时间轴，可用当前环境的 HyperFrames，先读对应技能。将成品放入整片主时间线时使用[黄白 Video Editor](https://github.com/huangbai-AI/huangbai-video-editor/blob/main/SKILL.md)。用其规范建立实际工程，注册暂停时间轴，媒体交由框架管理；运行当前版 `check` 并截图关键时刻。不要照抄旧版 `inspect`／`validate` 当成当前要求。
- 如需求指明其他框架，沿用用户选择。只取本技能的视觉／叙事原则，不为了风格擅自重建全部工程。
- 桌面界面在真实横屏下录制，局部录制、Screen Studio工程缩放或外层推拉／平移按镜头计划选择；保留raw和工程。缩放不得改变横纵比例；必要标注独立为图层，不烧进原文件再冒充原始画面。
- 不无关改写口播、补人物、替换素材或生成新的商品案例。需真人抠像、卡片在人前后遮挡时，再读 `talk-motion` 对应合成规则；只取空间、连续性和验收方法，默认配色仍以本技能为准。

## 轻量代码动效直接导出

若只需要本包这类无音轨的短动效，不必先搭复杂工程。把模板、style.css 和 huangbai-dot-grid.png 复制到本任务目录，用本地服务在 Ego Lite 打开；观察确认正确页面，再运行：

```js
// 由 ego-browser nodejs 执行；编号、标签、路径来自本次真实页面。
const {renderMotion} = await import('file:///absolute/SKILL_DIR/scripts/render-motion.mjs');
await renderMotion({
  spaceId: SPACE_ID, pageLabel: 'PAGE_LABEL',
  outputDir: '/absolute/task/work/broll/motion/shot-02-frames',
  width: 2160, height: 3840, duration: 8, fps: 30
}, {taskSpace});
```

再用 `encode-recording.py` 将该帧目录编码为 `shot-02.mp4`。采样器只适用于自己编写、提供 `renderAt(t)` 的代码页面；metadata 明确记为 `code-motion-sampled`，不能把它标为真实录屏。支持 24／25／30／50／60 帧，导出保留选择的帧率；长片拆成短镜头。模板在原生 2160×3840 画布绘制，默认是左向右扫描对比；加 `?demo=upload` 为截图连续拖入的示意动作。它们使用自带示意素材，不代表真实网站操作。正式制作须替换为获准素材；1080×1920 预览从 4K 母版缩小。原背景位图保留其原分辨率，不宣称它本身为原生 4K；4K 合成也不代表每份原始照片／视频的细节都变成原生 4K。

此路径为本地代码画面导出，不调用收费视频模型。带声音、复杂媒体、透明输出或多人协作工程时转用符合当前任务的制作工具。

## 代表段先行

批量制作前，先完成最能体现本次要求的短段：例如居中的搜索输入、从预览到右侧Agent的横向取景，或同位置扫描对比。用实际素材与声音节拍，在手机尺寸下观看；对照原技能的构图、主体比例、动作和质感，而非只比较色值。通常自行检查通过后扩展，不自动增加用户确认步骤。用户指定分段确认时，按实际确认范围继续。

## 最小验收

所有实际视频在生成、录制、合成或修改导出后，再执行[Codex 独立复检](post-render-review.md)。下列检查既是制作自检项目，也是独立检查者的检查范围；制作自检不替代独立复检。逐个覆盖所有交付视频及最终组合片，问题修复后对新导出版本复检，保留带文件摘要的检查记录。

Screen Studio 工程先按 [接入流程](screenstudio-recording.md) 核对分段顺序与独立声音轨，再交付可播放文件。工程保存成功和成片导出成功分别记录；不能把原始分段当作已含自动缩放的成片。

1. 录屏有真实连续帧，动作与结果都能对上，开头结尾留剪辑余量。
2. 动效中间状态正确：按 0、25%、50%、75% 和末帧定位；再逆序定位，画面必须一致，不能回放缺字／闪图。
3. 按[页面与界面原则](ui-principles.md)和[构图与口播组合](framing-and-layout.md)在手机观看尺寸检查：主体一眼可见，必要字直接可读，界面正常比例，四周避让，操作重点在中央；圆头像不遮操作，上下分屏确为界面＋本人。整页小字、贴顶搜索框、拉伸界面、主体缩成小卡片、用上下两个UI冒充人物分屏都不合格。
4. 动效对照原标准检查开场、动作中间和结果：截图与拖动是否同一对象连续完成，扫描对比是否真的揭示变化，主体是否清楚足够大，是否只是低清截图换字和反复叠化，是否有双字／双图重影、虚化重复铺底或同一版式拖满时长。不能只验色板、终态截图与导出尺寸。
5. 检查文件时长、尺寸、帧率、声音。原片有声音就保持原版；不擅自静音或换轨。无声路线明确标记“无声录屏”；用户要求声音但没录到时记为缺项，不能以无声文件当作完成。
6. 最终 MP4 使用 H.264、yuv420p、faststart；有声音时用 AAC 交付兼容副本，源文件另存。原生尺寸与放大尺寸分别记录。
7. 同时保留源码、镜头表和共用风格文件。上传、发消息、发布或写回源文档只在当前任务授权时执行，不由这个技能自动扩大范围。
8. AI 视频核对人物、产品、动作与实际原声，保留生成记录；组合段连续观看接缝，确认主体位置、比例、方向、亮度与声音衔接自然。动画示意与 AI 演绎不得被当作真实功能验证。

验收记录分开写“实际操作与结果”“构图与审美”“技术文件”。三项都通过才算交付完成；任何一项失败就定位镜头修改。用户已经指出构图或审美不合格时，将该版本记为待修／不合格，不能继续沿用此前的技术通过记录宣称合格。

## 结束时说什么

“已生成 3 段：1 段真实录屏、1 段说明动画、1 段 AI 演绎，以同一张素材衔接。素材、源码和生成记录在……。已检查实际结果、人物连续性与接缝；录屏为无声操作画面。”数量、类型与验证结论按实际填写，不套用示例。

不要说“全自动完成”来代替实际验证。仅脚本检查通过或完成本地测试页面，不能声称已验证所有第三方网站。
