# 构图、安全区与口播组合

先决定观众这一秒该看哪里，再选录制范围、画面组合和镜头运动。录下整个网页只是获得源素材；最终构图要让观众轻松看到操作、结果或本人的反应。

## 录制画幅与展示画幅分开

桌面软件在真实横屏显示器／浏览器窗口下操作，保持其正常布局和宽高比例。常见16:9、16:10或当前窗口实际比例均可，不为竖屏交付而改变成移动端页面。局部录制可以缩小记录范围，但源界面的文字、按钮、图标比例不变。

优先用 Screen Studio 录真实窗口或局部，保留工程和鼠标轨迹。输出9:16时，再决定横屏内容怎样进入竖屏：

- **单个动作**：裁取有必要上下文的局部，等比放大，把目标移到中央。
- **关注点横向转移**：用同一横屏录屏做平移或推拉。先让目标居中并停住，再操作；操作后移向对应结果，不机械把整张页面扫一遍。
- **需要交代软件位置**：短暂拉回横屏概览，再推近关键局部。概览不能占满整段，让观众一直读小字。
- **人与操作同等重要**：用上界面、下本人的各半分屏，界面在上半区内仍按原比例显示或取景。

所有缩放保持横纵一致。无法兼顾比例、必要上下文和字号时，换景别或分成前后两镜；不要把横屏挤成竖条，也不要从多个 UI 区块拼出一个看似真实的新布局。若确需界面局部插图，要明确它是后期取景，不能代替“上界面下本人”的人物分屏。

## 三种画面组合

| 组合 | 何时选 | 画面安排 |
|---|---|---|
| 纯口播 | 强调本人的反应、情绪、判断、观点或段落衔接 | 本人做主角；脸和手势清楚，不硬塞界面素材。没有口播原片且用户允许时，可用原照站位并注明待拍 |
| 纯录屏／辅助画面，可带小圆头像 | 强调怎么操作、发生了什么、结果如何 | 界面或结果是主角；可在右下方的安全范围内放本人小圆头像补反应。可不放头像；不得遮输入、按钮、轨道或结果 |
| 上下各半：上界面、下本人 | 操作与本人的解释／反应都要强调 | 上半区讲操作，下半区看本人，两者节拍对应；不把预览＋时间轴当成这类分屏，不再套多层可见边框 |

按句子和动作切换，不按章节固定。比如：本人提出问题（纯口播）→搜索演示（纯录屏）→操作同时解释关键判断（上下各半）→结果大特写（纯画面，可带圆头像）→本人反应（纯口播）。只有实际表达需要时才切换，不为了展示模板凑齐三种。

## 四周安全区约束重点，不裁黑整个画面

先检查目标平台实际预览、账号／互动栏、字幕与简介遮挡。未知平台时，可用下列**制作起点**，它们是本技能的构图建议，不是平台官方安全区。尺寸变化按比例换算，参数在 [framing.json](../assets/framing.json)。

以1080×1920为例：

| 范围 | 建议起点 | 用途 |
|---|---|---|
| 避让边缘 | 左10%、右14%、上10%、下20% | 关键按钮、搜索内容、结果文字、脸不贴边；右侧和底部额外防遮挡 |
| 纯画面主要关注范围 | 横向20%～80%、纵向25%～70% | 搜索输入、点击目标和结果的观看重心靠近中央；不要求整页都塞进此范围 |
| 圆头像 | 直径约画幅宽的16%～20%；圆心起点约(73%宽,70%高) | “右下角”指安全区里的右下方，不是画布最右下角；具体位置避开当前操作 |
| 上下分屏 | 分界线在50%高度 | 界面目标在上半区中央，本人脸在下半区可见安全范围；整张画布的外缘避让仍然生效 |

安全区外可以有正常界面、背景和人体非关键部分；不是四周空掉、上下加黑带，或把主体缩成中间小卡片。人物背景保留获准原片或安静的既定背景，不重复放大虚化同一张人像填外围。

每镜检查目标**整个可读范围**，不能只查中心坐标。长查询、弹出的菜单、鼠标点击点、头像圆边、下半区的人脸都可能越界。画面从A处移向B处时，中间运动状态同样要检查。

上述要求覆盖所有视频画面，不能因为是 AI 原片、录屏或纯口播就免检。最终导出后执行[Codex 独立复检](post-render-review.md)，在实际视频上检查，而非仅凭设计坐标或制作代码判断安全；修改后重新检查新版本。

四周避让适用于全部三种组合；表中的“纯画面主要关注范围”只适用于整幅纯录屏／辅助画面。上下分屏分别在上半区、下半区安排各自的焦点，不强迫两个主体都挤进纯画面的中央矩形。配置中的锚点是起点，不代替可读范围检查。

## 搜索演示的正确组织

1. 保持真实桌面网页，找到原本的搜索框；把录制局部或后期取景对准它。
2. 搜索框、放大后的查询文字位于画面中央；上下分屏时，位于上半区中央。保留搜索图标、框体或少量相关页面，观众认得这是搜索。
3. 输入过程、确认动作、实际结果依次发生。查询文字须在手机观看尺寸下直接能读，不用额外一段说明解释正在搜什么。
4. 结果出现后，镜头再平移或拉回到最有价值的几张结果，停留查看。若讲具体素材，再推近该素材。

关键字在1080宽成片中可先以约44～60像素的可见字高试排，4K等比翻倍；这不是网页原字号。以手机尺寸实际阅读为准。若放大后已经糊，改用更高质量捕获或重录重点局部，不锐化糊字冒充清楚。

**失败例**：整张页面一直露出，搜索框贴顶、字很小、下方全是无关结果；虽录到了真实操作，也不算合格搜索镜头。

## 横屏编辑器转竖屏的正确组织

Fotor Agent 这类编辑器需要保留真实桌面界面。按口播选择目标，例如：

| 台词／动作 | 观看任务与镜头 |
|---|---|
| 进入编辑器 | 短暂看清软件整体关系，然后进入正在讲的局部 |
| 选中要修改的元素 | 预览中的目标或时间线片段居中，留出选中前后的真实变化 |
| 在右侧 Agent 输入修改点 | 同一横屏源画面平移到右侧，输入区放大并居中；不让文字贴右沿 |
| Agent 修改完成 | 回到对应预览结果，先停住让观众看清变化；需要时再给参数验证 |
| 查看编排轨道 | 把当前要讲的几条轨道放大到中央，保留关联的时间标尺；不要求所有轨道和整个预览同时可见 |

左素材→中预览→右Agent可以从左向右移；中间选中→右侧输入→中间结果则移过去再回来。运动方向服务操作因果，不预设所有镜头都往同一方向扫。

## 开录前留下的决定

镜头表最少记：为什么选这类口播组合、源画幅／录制局部、关注对象、它在成片中的位置与可读大小、何时推近／平移／拉回、头像和平台遮挡如何避让。可以沿用工程现有字段，不为字段名改造旧工程。

先做一个代表性短段，在手机尺寸下看搜索输入或编辑操作；不能看清就先改取景，不先批量录完。代表段通过后再按相同标准扩展。这是制作自检，不自动增加用户审批步骤；用户明确要求分段确认时，以该要求为准，当前正文脚本须先交完整 Part 1，获认可后再制作后续部分。
