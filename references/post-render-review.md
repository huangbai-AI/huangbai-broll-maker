# 生成后由 Codex 独立复检

用户要求每轮视频制作完成后，再由 Codex 独立检查是否符合要求。生成成功、工程保存成功、导出成功都不能代替这一轮复检。素材制作阶段覆盖录屏、说明动画和 AI 视频等独立交付项。整片组合后由[黄白 Video Editor](https://github.com/huangbai-AI/huangbai-video-editor/blob/main/SKILL.md)安排复检，可复用下方检查方式。

## 固定收尾流程

1. 制作完成并导出最终文件，保存源工程、当前镜头表和声音。按视频内容选择目标平台的实际遮挡范围；未知时使用本技能 `assets/framing.json` 的制作建议，不能说成平台官方规范。
2. 准备独立检查材料。每个待交付视频运行 `scripts/prepare-review.py`，得到带安全区参考线的检查副本、抽帧和检查记录。源视频不改动，检查参考线不进入正式交付片。
3. 把独立复检交给另一个 Codex 检查上下文／子代理。用户已明确要求这种独立检查，可为本任务使用独立检查者；若当前环境没有此能力，明确标为“待独立复检”，不能用制作者自检冒充。不要只把它交给普通代码审查工具：检查者必须能实际看画面、播放视频，需要时听声音。
4. 检查者逐镜对照脚本、三种构图、原动效标准和实际视频，完整播放，再查看抽帧、放大细节与运动区间。问题记录到具体文件、镜头和时间点，给截图证据及修改方法。
5. 制作者修正，重新导出；只对修正后的文件重新准备材料和复检。检查被修改的镜头、前后接缝，并连看最终全片；不能套用旧版通过记录。技术、实际操作与画面审美均无未解决项才可标“复检通过”；用户另有分段认可要求时，复检不替代用户认可。

## 准备检查材料

本地只需 Python、ffmpeg 和 ffprobe：

```bash
python3 SKILL_DIR/scripts/prepare-review.py \
  --video /absolute/task/outputs/最终视频.mp4 \
  --out /absolute/task/work/review/shot-01-v2
```

`SKILL_DIR` 替换为实际技能目录。每次使用一个新检查目录；逐个检查所有最终交付视频，不仅检查其中一个样片。`--framing` 可指定本次平台配置，结构沿用 `assets/framing.json`。平台或构图与默认竖屏不同，先确定适用参数。

默认每0.5秒抽帧，并另取首帧及真正的最后一个解码帧；`--events events.json` 接受秒数数组，用于补充真实切点、快速移动、放大、弹窗或文字出现等时刻。对事件前后与运动中段密集取样；需要时用 `--interval 0.1` 准备更密集证据。抽帧不能穷尽瞬间问题，必须完整播放；高速变化处必要时逐帧查看原片。

`evidence.json` 保存实际视频信息、源文件摘要和抽帧记录；本次完整构图配置另存为 `framing.json` 并记录摘要，不只保存外缘参数。检查页提供原片入口，带线副本可能经过压缩和缩小，核对原始清晰度、声音或参考线覆盖的位置时必须对照原片。`review.json` 初始全部为 `pending`。此脚本只准备证据，不识别主体、不自动判定安全区合格，也不把抽帧或解码成功当作审美通过。检查者必须实际查看后填写判断，不能批量把状态替换成通过。

检查材料默认用于本机，原片入口指向当前原文件。移动、归档或转交检查目录时，应同时提供原片实际文件并核对摘要；不能把断开的链接当成可查看证据。

## 必查项目

- **安全区与遮挡**：检查关键文字、按钮、结果、脸部、小圆头像的整个可读范围，包含边界；放大和平移的全过程都检查，不只看中心点和终态。平台互动栏、昵称、说明及字幕可能遮挡重点。安全区外允许背景和非关键部分，不给画布强加黑带，也不把主体缩成小卡片。
- **三种构图**：纯口播看脸和手势；纯画面看操作／结果，头像不挡内容；上下分屏上界面、下本人，各自清楚，不能把上下两块界面当人物分屏。分屏焦点用各半区规则，不套纯画面的中央矩形。
- **比例、清晰度与对比**：真实桌面布局和横纵比例正常；手机尺寸能直接看清输入、按钮和结果。主体与背景拉开明暗和颜色对比，没有整段小字、贴顶搜索框、模糊放大或过多层级。
- **脚本与真实操作**：每条口播对应正确素材与动作，没有漏句、错画面、伪造成功状态或把原理示意当真实功能证明。表格允许相同连续画面的半句合行，但实际画面与说明应一致。
- **原风格与连续性**：对照黄白原动效标准检查主体大小、动作语言、拖入和扫描揭示，不能只检查颜色。播放没有明显跳帧、闪图、重影、突然跳位；同素材在运动中保持连续，转场不迫使观众重新找主体。
- **声音与文件**：实际音轨、口播节奏和画面对应；保留授权原声，不擅自静音或后配声音。确认尺寸、时长、帧率、可播放性及所需工程。导出30帧不等于网页源录屏实际30帧。

## 按画面组检查连续性与美感

逐个单元格从头检查到尾，不能只检查切镜点和安全区。按[连续录屏与提示词展示](continuous-screen-direction.md)核对原位圆角高亮、多列单向滚动、六网站的字体和网格、填好的提示词白框卡片与随后实际键入、完整编辑器、真实倍速过程及居中推近结果。记录突跳、乱动、漏过程和不好看的排版；字能读清、安全区合格，不代表这些项目通过。没有连续视觉观察时，相关项目保持未核实。

## 独立检查任务模板

> 请独立复检这些实际视频。先读本任务的用户要求、镜头表、framing.json、黄白原动效标准和 post-render-review.md，再完整播放每个文件并查看检查材料。自行判断，不依据制作者“已完成／已通过”的表述。检查所有镜头，重点看安全区、运动中段、文字可读性、真实比例、三种组合、脚本对应、原风格、连续性与声音。报告文件／镜头／时间点／画面证据／问题／修改建议。未能播放、未覆盖的部分或无法确认的项目标为未核实，不能通过。无需改文件或生成新素材；仅更新本次 review.json 并返回结论。

向检查者提供必要的用户约束、原始标准、实际文件和客观参数，不提供“这个版本应该通过”等预期结论。能提供直接视频播放能力就直接提供；只有抽帧而没有完整播放时，明确检查覆盖限制。

## 报告与交付门槛

记录实际检查者、是否独立、源文件摘要、完整播放是否完成、检查时间点和每项判断。每个问题写清哪一个对象、在何时怎样越界／不清楚，以及怎么修。状态可为 `pending`、`failed`、`passed`；未播放、未知、存疑都不能记通过。

发现问题就返回制作环节，不默许以“4K成功导出”等技术结果覆盖。若当前只能交待审版或存在已知限制，明确写“待独立复检／未通过”和具体缺项，不称正式合格成片。
